# Installation and recovery diagnostics / Diagnóstico

Private configuration contains absolute workspace/repository, H2, driver, media, service and state paths, an existing private launcher repository and branch, private GHCR destination, Worker origin and Cloudflare account. A public source checkout intentionally contains none of an operator's private captures, working catalog or credentials. The initial provisioning recipes are available in [English](installation.en.md) and [português do Brasil](installation.pt-BR.md). The executed operator walkthroughs and their scope are recorded in [VALIDATION.md](../../VALIDATION.md); no operator should copy another person's private files.

Keep `state/restoration.json` until the prior backend state is confirmed. Restore its exact service configuration before retrying if it differs. Check service ownership and H2 handles; never remove a database lock or signal a process inferred solely from a port. An initially stopped backend must remain stopped.

For recorded revisions, inspect private `operations/<revision>/journal.json`, `build.log`, `runtime.log`, `failure.json`, `image-evidence.json`, `local-validation.json` and `public-validation.json` when present. These are individual checkpoints, not proof that later stages completed. Raw captures remain under private staging on incomplete capture; they must never be copied to a Docker context or public repository.

The remote ref `refs/heads/enois-preview-publication-lease` identifies a serialized publication by its commit message operation ID. A remote outcome may be ambiguous after a lost acknowledgement. Resume queries the destination first. If identity remains unresolved, inspect the destination with the operator rather than deleting state or publishing another artifact. No force push or paid fallback is allowed.

The executor and private consumer require the same clean, fixed TypeScript commit. Resume verifies that revision's frozen sources, recipe, data and compiled artifacts; it never substitutes current live inputs. There is no historical executor allowlist or Python recovery. A GitHub creation refusal has a ten minute cooldown; allow idle environments to expire and use canonical `resume` after that window, without changing machines or plans.

All own records require `format: "enois-preview-ts-v1"`. This includes credentials `{format,accounts:[{id,email,label,password}]}`, configuration, data inventories, journals, provenance, tool locks, lifecycle state and catalog `{format,scenarios:{...}}`. Each catalog entry has that format, `revision`, exact ordered `accounts`, immutable `image`, `launcherCommit`, `devcontainerPath` and `provenanceSha256`. Existing TypeScript catalog entries are immutable. Historical `schema` 1/2/3 records, the single `{email,password}` callback and Python journals are refused before mutation; `--legacy-verification` and `resume-compatible-tools.json` are removed. Preserve old records and Git history and create a new installation at `~/.config/enois-preview-ts` or another `ENOIS_PREVIEW_HOME`. Old links are outside this version's contract.

Build first with `npm run build`. For acceptance diagnostics of fictional images only, `node dist/scripts/validate-delivery.js IMAGE PRIVATE_EVIDENCE_DIRECTORY` exercises the packaged direct and asynchronous newsletter services with a recording mail transport and a positive control. `node dist/scripts/validate-integration-isolation.js IMAGE PRIVATE_EVIDENCE_DIRECTORY` boots a separate copy of the packaged fictional seed, blocks JDK HTTP through an observed proxy, exercises six scheduled entry points and an eligible deletion of a retained external asset, and checks that external storage and lazy migration beans are absent. These local probes complement public content, notification and media exercises; their transport doubles do not represent live deliveries or all possible application behavior.

Diagnostic scenario preparation uses `node dist/scripts/add-scenario.js SLUG IMAGE_DIGEST HTTPS_ORIGIN OWNER/REPO NEW_PROVENANCE_JSON`. It requires versioned provenance matching the image and refuses an existing slug. After committing the configuration and provenance, `node dist/scripts/pin-scenario.js SLUG FULL_CONFIGURATION_COMMIT` compares every file with that Git commit before appending the catalog. These commands support inspection; normal publication and recovery use the canonical CLI.
