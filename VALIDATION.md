### Executed validation

`npm test` passes 41 Node tests and 60 Python tests, including complete CLI recovery after upgrading a private consumer and removing live sources/data. The one skip in public/installed sources is intentional: private historical Git objects must not be distributed. The private worktree separately executes the real historical comparison. `npm run check` passes for the public tool and actual private consumer. Exported application builds pass 878 frontend tests, typecheck/build, 19 selected backend contract/storage/sanitizer/blog tests and DS build/dist checks. Python 3.10 variable-fraction parsing is covered; the focused deployment suite also passed on Python 3.12.

The two final public example preparations have canonical data SHA256 `0fd5764b41b67082f18ce42059bded059afc49a91917223f2e0680c5816f5d56` and identical nine-file media inventories. H2 binaries are not required to be byte-identical. Mobile checks are Chromium emulation, not a physical device. Live platform checks use this operator's existing private infrastructure and matching initial verification. New-account provisioning instructions were reviewed with official documentation and generated consumer validation; a separate new platform account was not created. No live billing API audit or deliberate quota exhaustion was performed.

Initial confirmation/refusal, provider failure injection, complete lost acknowledgements and literal millisecond lifecycle boundaries include explicitly controlled doubles. Actual public browser/API/capacity/lifecycle and both final operator walkthroughs are separate evidence. A passing suite does not substitute for their observed results.

### Failures found and recovery

The real tunnel refused a valid 20 MiB request with HTTP 413. Authenticated internal parts of at most 8 MiB now stream into one original backend request, preserving authorization, CSRF and the shared reservation; historical images do not receive that capability. The actual public exact boundary and capacity race subsequently passed. Failed earlier capacity attempts are retained separately and are not counted as passing evidence.

AVIF loading required the Noble runtime's libheif installation and explicit native access. Audio WebM remuxing required a supported temporary container suffix. The complete subsequent public MIME matrix passed. Login testing exposed native GET fallback before hydration; the demo export now uses POST and disables submission until hydration, with JavaScript-disabled regression coverage. The affected private error log was redacted.

Acceptance also exposed shared Node Web Locks in an unisolated legacy session test, oldest-first Cloudflare deployment history, valid variable timestamp fractions rejected by Python 3.10, and a consumer-pin comparison against a frozen instead of current executor. Each correction has behavioral regression coverage; no timeout/assertion was relaxed. Complete CLI recovery and actual public resume preserve original revision/input/image identities while recording the corrected executor separately. Compatibility is explicitly declared in release/resume-compatible-tools.json; arbitrary tool-version mixing remains rejected.

Actual provider/public checks returned refusals and transient 404/503 during publication. The CLI returned nonzero with frozen journals and canonical recovery instructions, preserving registry/config/catalog/deploy checkpoints. Both released-language workflows subsequently completed with canonical resume. Parallel D2 functional/MIME checks also returned one feed 401 and upload 502; readiness stayed healthy and passwords did not rotate. The precise cause remains unknown. Isolated complete functional and MIME runs passed afterwards. Repeating fixed fictional content correctly triggered duplicate protection, so acceptance fixtures now use unique content per run; that protection remains active.

### Remaining risks and practical limits

One earlier Jammy/Java 25 prototype exited with SIGSEGV after ONNX native initialization. Later Noble boots and all stated checks passed, but no root cause is established for that isolated crash. It is not presented as a proven fix. The pinned DS development audit reported two critical advisories while its production-only audit reported zero; application commits were not silently changed. Known-control layer/source scans complement real authentication checks and explicit source allowlists; they are not universal secret detectors.

No required criterion above is left as planned-only evidence within the stated Linux/existing-infrastructure scope. These results do not promise universal host/LLM compatibility, uninterrupted platform availability or permanent hosting. Immutable revision identity is distinct from shared, disposable runtime state. Ten minutes without accepted activity starts deletion; quotas and provider access still constrain operation. Credentials and new uploads rotate/disappear at a new boot. The Codespaces terms and absence of formal GitHub approval for this architecture remain explicit in both READMEs.
